## 描述

把想法变成可交接的方案文档：（可选）先和方案顾问聊清楚想法（问答、梳理、验证可行性，整理成 IDEA.md，你回复“确认想法”或“不做了”）→ 调研 → 2–4 个简要方案并推荐 → 人工选定 → 详细方案文档 → 评审循环（最多 5 轮，超出转人工）→ 输出交接文档 HANDOFF.md；用户回复“交给开发”后，同一任务改派给「开发实施小队」规划与实现。本小队不写 PLAN.md、不改业务代码。

## 成员

| 成员 | 小队角色 |
|---|---|
| 方案评审总管 | leader |
| 方案顾问 | 项目问答、想法梳理与快速可行性核对（EXPLORE 阶段，整理 IDEA.md，不替用户选方案） |
| 方案调研师 | 调研并给出 2–4 个简要方案和推荐（OPTIONS.md） |
| 方案文档师 | 写详细方案、处理评审意见、生成交接文档（DESIGN.md / DECISIONS.md / HANDOFF.md） |
| 方案评审员 | 只读评审详细方案（REVIEW_<N>.md） |

## 小队指引

```md
# 调研方案小队指引

阶段规则以方案评审总管的指令为准，这里只是路由摘要：

- 用户还没有清晰想法（提问、只有感觉、想先验证想法行不行、需要先聊清楚），或在其他阶段提出与当前选择/裁决无关的纯提问 → 方案顾问（问答、梳理想法、快速可行性核对、整理 IDEA.md）
- 用户用“开始调研：<想法>”给出想法、在顾问整理好 IDEA.md 后回复“确认想法”、回答方案调研师的问题或要求修订方案 → 方案调研师（OPTIONS.md）
- 用户用“选择方案 <编号>”选定方案、需要处理评审意见或生成交接文档 → 方案文档师（DESIGN.md / DECISIONS.md / HANDOFF.md）
- 评审当前 DESIGN_VERSION → 方案评审员
- 成员运行被取消或没有回复，用户回复“重新派活” → 队长把当前阶段的活再派一次
- 任何等用户回复的时候（聊、确认想法、选方案、评审裁决、交接决定等），用户回复“不做了” → 队长记下结论，把任务推到 in_review
- HANDOFF.md 生成后：用户回复“交给开发”→ 队长把本任务改派给开发实施小队；“暂不交给开发”→ 推到 in_review

方案顾问回复后队长保持沉默，等待用户下一条消息；用户回复“继续聊”或“按以下意见调整：<意见>”时仍交方案顾问。用户直接 @ 某个成员时由该成员处理，队长被唤醒后不重复派活。
```
