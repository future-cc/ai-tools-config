# Figma 还原工作流（固定层）

> 本文件由 `figma-restore-init` 原样复制到项目中，所有项目通用。不要在项目里改写本文件；要改流程，改 `ai-tools-config/shared/skills/figma-restore-init/workflow.md`，再在各项目重新运行 `figma-restore-init`。
>
> 项目相关的信息（技术栈、基准宽度、适配方式、token 对照表、可复用组件、本机环境）在同目录的 `SKILL.md` 里。两者冲突时，以 `SKILL.md` 的项目信息为准，但本文件的流程和禁止事项不能放宽。

## 总原则

- 设计稿不规范（绝对定位、没有 Variables、图层名混乱）是常态。**Figma MCP 的输出只当“参考数据 + 截图”，不能照搬成代码**，要按项目的布局方式、组件和 token 重写。
- 截图和结构数据冲突时，以截图的视觉效果为准，再用结构数据取精确数值。
- 不确定就问，不猜。
- Figma MCP 不可用（未配置、连不上、取不到节点）时，停下告诉用户原因，不要凭记忆或想象还原设计稿。用户改为提供截图时，可以只按截图分析，但要在分析结果里注明“无结构数据，数值为估算，需人工核对”。

## 阶段一：分析（不写代码）

1. **确认范围**：用户给出 Figma 链接或 node-id，以及要改的页面 / 组件。缺任何一项先问。判断是“新建页面”还是“修改已有页面”。
2. **分块取设计数据**：按区块（导航栏、卡片、列表项、底部栏……）逐个取，每块同时取结构数据和截图。不要整页一次取完。
   - 输出被标记为稀疏、截断或明显缺内容时，对照截图找出子节点 node-id，单独请求子节点。
3. **读现有代码**：修改已有页面时，先读当前页面代码、它用到的组件、数据模型和状态管理。
4. **折叠屏**：看 `SKILL.md` 的“折叠屏”一节。写“不支持”或没有这一节时，跳过所有折叠屏相关内容。支持时，检查设计稿有没有内屏（展开）版本：
   - 有：按内屏设计稿实现。
   - 没有：在疑问点里问“这个页面的内屏用默认策略（写出 `SKILL.md` 里的策略），还是需要特殊处理”。不要自行发明内屏布局。
5. **输出分析结果**，按下面的格式，然后**停下等用户确认**：

```markdown
## 还原分析：<页面名>

### 1. 逻辑对照表
| UI 元素 | 显示内容 / 数据字段 | 代码中的对应 | 状态 |
|---|---|---|---|
| 订单标题 | 订单号 | order.id | 已有 |
| 优惠标签 | 优惠金额 | — | 代码缺失 |

页面状态：空态 / 加载 / 错误 / 正常，各自在设计稿里是否有，代码里是否有。
交互：点击、跳转、弹窗，设计稿和代码各自的表现。

### 2. 差异清单（修改已有页面时必填）
- 要改：<具体元素，从什么改成什么>
- 要新增：<元素>
- 不动：<明确列出不改的部分>

### 3. 尺寸与适配
设计稿画板宽度 <x>，项目基准宽度 <y>，换算方式 <按 SKILL.md>。
哪些元素固定尺寸，哪些自适应。
支持折叠屏时：内屏有没有设计稿；内屏采用的布局策略；切换时需要保留的状态（输入内容、滚动位置、弹窗等）。

### 4. 数值归并
设计稿中的原始值 → 项目 token（按 SKILL.md 的对照表）。
对照表里找不到的值单独列出，给出建议的归并目标。

### 5. 疑问点
- UI 有、代码没有的字段，数据从哪来？
- 设计稿里看不清或互相矛盾的地方
```

用户确认或修正后，才进入阶段二。用户明确说“直接做”时可以跳过等待，但分析结果仍要先输出。

无人值守运行时（例如作为 Multica 等平台的智能体执行任务），把分析结果发到任务评论或任务指定的位置，然后停止，等用户回复后再继续；不要因为没人回复就自行进入阶段二。

## 阶段二：实现

### 必须遵守

- **只改阶段一确认的范围**：修改已有页面时只改差异清单内的内容；新建页面时只新增确认过的页面和必要的接入点（路由、入口）。范围外的代码、逻辑、接口调用、样式一律不动；发现范围外也需要改时，停下问用户。
- **布局**：外层容器和区块禁止写死宽高、禁止绝对定位，用项目的弹性布局方式（flex、Row/Column、Stack 等）。只有图标、头像、固定尺寸的图片等本身固定大小的元素保留固定尺寸。设计稿里的绝对坐标要还原成间距和对齐关系。
- **尺寸换算**：按 `SKILL.md` 里的基准宽度和适配方式换算，不直接照搬设计稿画板上的像素。
- **数值**：颜色、字号、字重、间距、圆角、阴影，先查 `SKILL.md` 的 token 对照表，用项目已有的变量或主题值。禁止自行估算；禁止新增魔法数字。对照表里没有的值，按阶段一确认的归并结果处理。
- **组件**：优先复用 `SKILL.md` 列出的组件和项目里已有的组件，不新建功能重复的平行实现。现有组件确实不支持设计时，先说明原因再扩展它。
- **文本**：文案取设计稿原文，不改写；需要国际化的项目按项目方式处理。
- **图片和图标**：按 `SKILL.md` 指定的方式导出到指定目录。多路径 SVG 图标导出后检查是否变形；导不出或变形的，用占位并在汇报里列出，不要用错误的图标冒充。
- **折叠屏**（`SKILL.md` 写“支持”时）：内屏按阶段一确认的策略实现；按当前窗口宽度切换布局（如 `LayoutBuilder`、`MediaQuery` 宽度、CSS 媒体查询），不要按机型或品牌判断；折叠 / 展开时不能丢失页面状态。
- 不提交代码，不切分支。
- 项目不是 git 仓库时（见 `SKILL.md` 的“版本管理”）：改动已有文件前，把原文件复制到 `.figma-restore-backup/<日期时间>/`（保持相对路径），汇报时用备份和现文件对比。

### 容易出错的地方（逐项检查）

- 圆角加在了错误的边或错误的元素上
- 阴影、渐变、透明度遗漏
- 文字截断、换行、行高
- 列表项间距和首尾留白
- 安全区、状态栏、底部手势条区域
- 深色模式（项目支持时）
- 折叠屏内屏被直接拉伸：列表、按钮、图片过宽（项目支持折叠屏时）

## 阶段三：校验

1. 能运行和截图时（见 `SKILL.md` 的本机环境）：
   - 按 `SKILL.md` 的“校验用的尺寸”逐个截图；没写时，用设计稿宽度加一窄一宽两种常见尺寸。
   - 与 Figma 截图逐区块对比，列出差异并自行修正，最多三轮。
   - 三轮后仍有差异，停下，在汇报里列出。
   - 为模拟尺寸改过设备设置（如 `adb shell wm size`）的，校验结束（包括中途停下）必须恢复原设置，并在汇报里写明已恢复。
2. 支持折叠屏时，按 `SKILL.md` 的折叠屏校验方式：
   - 外屏（折叠）和内屏（展开）分别截图，与对应设计稿或确认过的布局策略比对。
   - 能模拟折叠 / 展开切换时，在页面有输入内容、滚动到中部的状态下切换，检查布局是否正常、状态是否保留。
   - 只能用 `wm size` 模拟宽度时，在汇报里写明“未测试折叠 / 展开切换和铰链”。
3. 不能截图时，说明原因，按“容易出错的地方”逐项自查，并给出用户手动检查的要点。
4. 运行项目的静态分析和相关测试。

## 汇报

- 改动的文件和 `git diff --stat`（不是 git 仓库时：新增 / 修改的文件清单和备份目录位置）
- 对照阶段一确认的范围（差异清单），逐项说明完成情况；确认没有改动范围外的内容
- 各尺寸下的截图对比结论（支持折叠屏时，包括外屏、内屏和切换的结论，以及没测到的部分）
- 未解决的问题：占位图标、无法还原的细节、仍存在的视觉差异
- 新出现、对照表里没有的设计值（建议补进 `SKILL.md`）
