# Multica 当前工作流摘要

## 上游输入

调研和方案选择由「调研方案小队」完成，输出 `HANDOFF.md`。个人开发工作流总队以 `HANDOFF.md`（或需求已清楚的简单任务）为输入，只负责技术设计、实现和验证。需求模糊或需要选方案时，工作流总管停止并建议先交调研方案小队。

## 小队任务启动

小队任务第一次运行时，工作流总管只做最低限度读取（含存在时的 `HANDOFF.md`），然后输出：

- `WORKFLOW_VERSION`
- 任务理解、范围和排除项
- 验收标准、风险和依赖
- 必调用与条件调用智能体
- 调用顺序、职责、触发条件和文件权限
- 预期产物

随后等待人工批准。第一道批准只允许架构师生成规划文档，不授权技术审核、代码修改、测试或完成任务。

## 计划审核

```text
[HANDOFF.md]
→ 架构师生成 PLAN.md（技术架构）
→ 人工审核 PLAN_VERSION
→ 方案与实现审核员技术审核
→ 架构师生成 IMPLEMENTATION.md / TEST_PLAN.md
→ 技术审核实施文档
→ OpenCode 执行
→ 通用测试员测试
→ 最终代码审核
```

`PLAN.md` 任何修改都会使旧人工批准失效，必须升级版本并重新人工审核。实施文档默认由技术审核员审核；只有改变范围、架构、接口、数据结构、用户可见行为或涉及高风险操作时，才重新请求人工审核。

## 结果和循环

审核和测试只使用 `PASS`、`CHANGES_REQUIRED`、`BLOCKED`。修订、修复和复测最多两轮，超过后暂停并等待人工决策。
