## 描述

个人开发任务的技术实现与验证：以调研方案小队的 HANDOFF.md（或需求清楚的简单任务）为输入 → 实施架构师生成 PLAN.md → 实施审核员审核 PLAN.md → 人工确认 → IMPLEMENTATION.md/TEST_PLAN.md → 实施审核员审核实施文档 → 实施工程师执行 → 实施测试员测试 → 实施审核员最终代码审核。不做调研和方案选择；当前分支、当前目录，不使用 Git worktree。

## 小队指引

```md
# 开发实施小队指引

阶段规则、审批关卡、版本和循环上限以实施总管的指令为准，这里只是路由摘要：

- 需求模糊、需要调研或选方案 → 不在本小队处理，建议用户先交「调研方案小队」产出 HANDOFF.md
- 生成或修订 PLAN.md、IMPLEMENTATION.md、TEST_PLAN.md → 实施架构师
- 审核 PLAN.md、实施文档和最终代码 → 实施审核员
- 按已通过的实施文档改代码、修复测试问题 → 实施工程师
- 测试与复测 → 实施测试员
- 审批（固定格式回复“批准 WORKFLOW v<版本>”“批准 PLAN v<版本>”“批准实施文档 v<版本>”；高风险任务在 in_review 阶段验收）→ Kane Kane

成员回复只是进展更新、没有需要决定的事项时，保持沉默。
```
