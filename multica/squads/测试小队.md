## 描述

根据产品文档、git 日志或接口文档，为手机 App 编写 Maestro 测试用例并执行，汇报结果：检查任务描述（缺项向用户要）→ 整理验收点与用例清单 → 人工批准 → 编写 Flow（写入被测 App 源码仓库的 maestro/<任务编号>/ 目录）→ 执行；失败后列出失败内容，由用户决定下一步。不修改被测 App 的业务代码；当前只支持 Android 和 iOS。

## 成员

| 成员 | 小队角色 |
|---|---|
| 测试总管 | leader |
| 测试分析师 | 验收点与用例清单（TEST_CASES.md） |
| 测试用例师 | 编写 Maestro Flow |
| 测试执行员 | 执行并汇报结果 |
| 测试排查员 | 失败归因（只读） |
| Kane Kane | 人工审批人 |

## 小队指引

```md
# 测试小队指引

阶段规则以测试总管的指令为准，这里只是路由摘要：

- 整理验收点、修订用例清单 → 测试分析师
- 编写或修改 Flow → 测试用例师
- 运行测试 → 测试执行员
- 失败归因 → 测试排查员
- 审批与决定（“批准用例 v<版本>”；失败后“修改用例：<意见>”“修改验收点：<意见>”“重新执行”“结束测试”；疑似旧版本时“安装包已更新：<路径>”；已安装模式“确认已安装最新版本”）→ Kane Kane

成员回复只是进展更新、没有需要决定的事项时，保持沉默。
```
