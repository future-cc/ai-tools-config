# Multica 跨电脑恢复指南

## 给执行恢复的 AI

1. 先读取本目录 `README.md`，不要直接修改 Multica。
2. 检查目标工作区、在线运行时、可用模型和认证状态。
3. 输出拟创建、修改、跳过和阻塞项目，等待人工确认。
4. 已存在且一致的配置跳过；已存在但不同的配置先报告；不存在的配置才创建。
5. 不删除现有智能体或小队，不覆盖无法判断来源的人工配置。
6. 并发、Skills、MCP、集成、开场建议和高级设置保持默认即可，但 `README.md` 列出的工作流依赖项（如实施工程师并发为 1）必须设置；模型不得静默替换，也不得把所有角色设为默认模型。
7. 每个阶段修改后读取并验证结果；失败时停止，不继续批量修改。
8. 最后输出成功项、替代模型、差异、阻塞和人工待办。

## 恢复顺序

1. 安装并登录 Multica，确认目标工作区。
2. 添加本地运行时，分别完成 Claude、OpenCode、Codex 等所需 CLI 认证。
3. 按 `README.md` 检查首选模型；缺失时先报告替代方案。
4. 逐个读取 `agents/*.md` 创建或更新智能体。
5. 读取 `squads/` 下的小队文件，恢复队长、成员、角色和指引。
6. 读取 `workflow.md` 核对完整流程。
7. 按下方清单验证并运行一个低风险测试任务。

## 幂等与回滚

- 已存在且一致：跳过。
- 已存在但不同：先报告差异并等待批准。
- 不存在：创建。
- 失败时依据恢复前快照还原被本次操作修改的字段，不删除原有配置。
- 无法判断来源的配置保持不变并标记 `BLOCKED`。

## 验证清单

- [ ] 十四个智能体均存在，名称、头像、描述、模型、运行时和访问权限正确。
- [ ] Claude、OpenCode 等所需 CLI 已认证。
- [ ] 开发实施小队（共 5 名成员，含队长和人工审批人）、调研方案小队（队长 + 5 名成员）和测试小队（队长 + 5 名成员，含人工审批人）的队长、成员、角色和指引正确。
- [ ] 实施工程师并发为 1；测试执行员并发为 1。
- [ ] 测试小队 5 个智能体指令里的 maestro-testing-kit 路径已换成新电脑上的实际路径。
- [ ] 测试小队：测试失败后总管列出失败内容并等待用户的固定格式回复，不自行修复或重跑。
- [ ] 开发实施小队没有单独的测试环节：工程师完成后直接最终审核，手机 App 完成时总管附测试小队任务描述模板。
- [ ] 实施总管首次运行会展示任务理解、必调用和条件调用智能体；有 HANDOFF.md 时只列补充或不同之处。
- [ ] 调研方案小队完成后回复“交给开发”，同一任务能改派给开发实施小队，实施总管能接手。
- [ ] 人工批准 `WORKFLOW_VERSION` 前不会调用其他成员。
- [ ] 第一道人工作流批准只允许生成规划文档。
- [ ] `PLAN.md` 先经实施审核员技术审核，通过后才等待人工批准对应 `PLAN_VERSION`。
- [ ] 只有“批准 WORKFLOW v<版本>”“批准 PLAN v<版本>”等固定格式的回复才算批准。
- [ ] 计划修改会使旧批准失效。
- [ ] 只有实施工程师可以修改业务代码。
- [ ] 实施文档默认技术审核，重大变化才重新请求人工确认。
- [ ] 低风险测试任务可以完整走通且没有重复调用。

## 凭证安全

禁止保存或复制密码、API Key、Token、Cookie、OAuth 会话、CLI 登录文件、本地密钥和设备凭证。运行时在线不代表模型提供商已经认证；认证失败必须停止并报告。
